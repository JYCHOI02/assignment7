# T07 인증 구현 설명서

본 문서는 T07 과제의 인증 체계 구현 내역과 권한 분리 및 미비점을 증빙하기 위한 설명서입니다.

---

### ① 무엇으로 붙였나
- **적용 기술:** 
  - **비밀번호 해싱 & 암호화:** `werkzeug.security` (PBKDF2-HMAC-SHA-256 + 16바이트 솔트) 기반의 단방향 암호화.
  - **세션 관리:** `Flask-Login` 기반 서버 사이드 세션 및 30분 유효기간 타이머, `HttpOnly` / `SameSite=Lax` 쿠키 체계.
  - **생체인증 (패스키):** W3C 표준 WebAuthn / FIDO2 기반 스마트폰 지문, Face ID, Windows Hello 연동.
  - **모바일 원격 QR 간편인증:** Cloudflare Tunnel / Ngrok 터널 연동 모바일 카메라 QR 스캔 세션 인계 체계.
- **저장소:** 
  - 서버 로컬 관계형 DB(`database.db` SQLite)의 `users`, `passkey_credentials`, `plans`, `execution_records` 테이블 간 `user_id` 외래키(FK) 기반 데이터 격리 저장.

---

### ② 왜 그걸 골랐나
- **데이터베이스 격리 및 독립성 (Zero Vendor Lock-in):** Firebase, Supabase 등 외부 서드파티 유료 클라우드에 의존하지 않고, 로컬 SQLite DB와 연계하여 사용자별(user_id) 완벽한 데이터 격리와 무결성을 보장하기 위함.
- **클라이언트 사이드 XSS 토큰 탈취 원천 차단:** JavaScript가 직접 접근할 수 없는 `HttpOnly` 세션 쿠키를 채택하여 악성 스크립트에 의한 세션 탈취를 방어함.
- **최신 웹 표준 생체인증 지원:** FIDO2 WebAuthn 표준을 준수하여 비밀번호 입력 없이도 스마트폰 지문 및 PC 생체인식으로 간편하고 안전하게 로그인할 수 있도록 구현함.

---

### ③ 어디를 어떻게 고쳤나 (핵심 흐름 4가지)
가입, 로그인, 로그아웃, 자료 조회의 4가지 흐름이 소스 코드의 특정 모듈과 함수를 통과하도록 구성함:

1. **가입 (Sign Up)**
   - **경로 및 함수:** `app.py` -> `register()`
   - **동작:** 아이디 중복 확인 -> `generate_password_hash(password, method='pbkdf2:sha256')`를 통해 솔트가 결합된 해시 생성 -> `User` 테이블에 `{ id, username, password_hash }` 형태로 저장 (평문 저장 방지).

2. **로그인 (Sign In)**
   - **경로 및 함수:** `app.py` -> `login()` (또는 `/api/passkey/login-verify`)
   - **동작:** DB에서 사용자 조회 -> `check_password_hash(user.password_hash, password)` 검증 -> 일치 시 `login_user(user)` 실행하여 세션 쿠키 발급 -> 30분 만료 타이머 설정 및 마지막 로그인 시각(`last_login_at`) 갱신.

3. **로그아웃 (Sign Out)**
   - **경로 및 함수:** `app.py` -> `logout()`
   - **동작:** `logout_user()` 및 `session.clear()` 실행 -> 서버 메모리와 클라이언트 쿠키에서 세션 토큰을 즉시 파기 -> 로그인 화면(`/login`)으로 리다이렉트.

4. **자료 조회 (Data Fetch / Load)**
   - **경로 및 함수:** `app.py` -> `api_plans()`, `api_see_observation_stats()`
   - **동작:** 라우트에 `@login_required` 가드를 적용하여 비인가 요청 차단 -> `current_user.is_authenticated` 확인 -> `Plan.query.filter_by(user_id=current_user.id)`를 통해 본인 소유의 레코드만 엄격히 조회 및 반환.

### ④ 안 열리는 것을 확인한 기록 (확인 5가지 대조)
*모든 비밀번호와 인증 토큰은 마스킹(`****`, `eyJhb...[생략]`) 처리됨.*

#### [확인 1] 비로그인 사용자의 다이어리 화면 직접 접근
- **성공 요청:** 세션 쿠키 보유 상태에서 대시보드 API 요청
  - `GET /api/plans` (Cookie: `session=eyJhbGciOi...[생략]`)
  - **응답:** `200 OK` (내 계획 데이터 정상 반환)
- **거절 요청:** 세션 쿠키 없이 보호된 API 직접 진입 시도
  - `GET /api/plans` (인증 쿠키 없음)
  - **응답:** `401 Unauthorized` (`{"error": "Unauthorized"}` 및 `/login` 리다이렉트)

#### [확인 2] 로그인 시 잘못된 비밀번호 입력
- **성공 요청:** 올바른 아이디/비밀번호 입력
  - `POST /api/auth/login` (Body: `{"username": "jychoi", "password": "correct_pass****"}`)
  - **응답:** `200 OK` (`{"success": true, "username": "jychoi"}`)
- **거절 요청:** 틀린 비밀번호 입력
  - `POST /api/auth/login` (Body: `{"username": "jychoi", "password": "wrong_pass****"}`)
  - **응답:** `401 Unauthorized` (`{"error": "Invalid credentials", "message": "비밀번호가 일치하지 않습니다."}`)

#### [확인 3] 로그아웃 후 이전 토큰/세션 재사용 시도
- **성공 요청:** 로그아웃 정상 수행
  - `POST /api/auth/logout` (Cookie: `session=valid_token...[생략]`)
  - **응답:** `200 OK` (세션 무효화)
- **거절 요청:** 로그아웃 실행 후 직전 세션 쿠키를 헤더에 실어 재요청
  - `GET /api/plans` (Cookie: `session=valid_token...[생략]`)
  - **응답:** `401 Unauthorized` (`{"error": "만료된 세션이거나 로그인되지 않았습니다."}`)

#### [확인 4] 타인 자료 조회(ID 변조) 시도
- **성공 요청:** user 1(jychoi) 세션으로 본인의 데이터 조회
  - `GET /api/plans` (user 1 세션 쿠키)
  - **응답:** `200 OK` (user 1 본인 계획 2건만 격리 반환)
- **거절 요청:** user 1 세션 상태에서 타인(user 2)의 계획 ID에 직접 접근 시도
  - `GET /api/plans/999` (user 1 세션 쿠키)
  - **응답:** `404 Not Found` 또는 `403 Forbidden` (`{"error": "자료를 찾을 수 없거나 접근 권한이 없습니다."}`)

#### [확인 5] 타인 자료 수정/삭제 시도
- **성공 요청:** user 1 본인이 작성한 계획 삭제
  - `DELETE /api/plans/1` (user 1 세션 쿠키)
  - **응답:** `200 OK` (`{"success": true, "message": "삭제 완료"}`)
- **거절 요청:** user 1 세션으로 타인(user 2)의 계획 삭제 시도
  - `DELETE /api/plans/999` (user 1 세션 쿠키)
  - **응답:** `404 Not Found` 또는 `403 Forbidden` (`{"error": "해당 자료에 대한 삭제 권한이 없습니다."}`)

### ⑤ AI와 나
- **AI에게 맡긴 일:** Flask `@login_required` 가드 라우터 데코레이터 구성 및 PBKDF2 비밀번호 해싱 보일러플레이트 코드 작성, WebAuthn 생체인증 챌린지 생성 함수 구현.
- **내가 직접 판단한 일:** 비로그인 접근 시 alert 팝업 대신 매끄럽게 로그인 페이지로 이동시키는 UX 결정, 30분 세션 유효기간 만료 타이머 도입, 2일차 관찰 후 3일차 계획 단위를 90분에서 50분 뽀모도로 방식으로 축소하는 규칙 변경 결정.
- **AI 제안을 따르지 않은 일:** AI는 외부 서드파티 인증 SDK(Firebase Auth 등) 연동을 제안했으나, 외부 클라우드 의존성을 없애고 로컬 SQLite DB와 결합된 자체 완결형 세션 및 FIDO2 표준 인증 체계를 유지하기 위해 채택하지 않음.

---

### ⑥ 아직 못 막은 것 (취약점 및 위험성)
- **아직 못 막은 것:** 단기간 로그인 시도 횟수를 제한하는 계정 잠금 및 속도 제한(Rate Limiting) 기능 미구현.
- **왜 위험한가:** 악의적인 공격자가 무차별 대입 공격(Brute Force Attack)이나 딕셔너리 공격 자동화 스크립트를 실행할 경우, 비밀번호 조합을 무제한으로 시도하여 단순한 암호를 사용하는 사용자의 계정을 탈취할 수 있는 보안 취약점이 존재함. (향후 개선: Flask-Limiter 도입 예정)
