## 1. 인증 구현 설명서 (6개 항목 전문)

### ① 무엇으로 붙였나
- **비밀번호 해시 및 검증:** `werkzeug.security`의 `generate_password_hash` / `check_password_hash`를 사용한 PBKDF2 SHA-256 솔팅(Salt) 암호화.
- **세션 관리 체계:** `Flask-Login` 기반 서버 사이드 세션 및 30분 유효기간 타이머, `HttpOnly` / `SameSite=Lax` 쿠키 적용.
- **기기 생체인증 (패스키):** W3C 표준 WebAuthn / FIDO2 기반 스마트폰 지문, Face ID, Windows Hello 연동.
- **모바일 원격 QR 간편인증:** Cloudflare / Ngrok 터널 기반 보안 토큰 교환 모바일 카메라 스캔 세션 인계 체계.

### ② 왜 그걸 골랐나
- **데이터베이스 주권 및 무결성 (Zero Vendor Lock-in):** 외부 유료 SaaS(Firebase, Supabase 등)에 개인 일정 데이터를 맡기지 않고 자체 SQLite DB와 연계하여 사용자별(user_id) 완벽한 데이터 격리 보장.
- **웹 표준 보안 준수:** FIDO2 패스키 표준을 준수하여 비밀번호 없이도 기기 생체인식으로 안전하게 인증.
- **멀티 디바이스 환경 지원:** PC뿐만 아니라 스마트폰 카메라를 통해 모바일-데스크톱 간 매끄러운 인증 세션 연결.

### ③ 어디를 어떻게 고쳤나 (핵심 흐름 4가지)
- **1) 회원가입 (Sign Up):** `app.py` &rarr; `register()`
  - `generate_password_hash(password, method='pbkdf2:sha256')`로 비밀번호를 솔팅 해시하여 DB `User` 테이블에 안전하게 저장.
- **2) 로그인 (Sign In):** `app.py` &rarr; `login()`
  - `check_password_hash(user.password_hash, password)` 검증 후 `login_user()`로 세션 쿠키 발급, 30분 만료 타이머 설정 및 마지막 접속 시각 갱신.
- **3) 로그아웃 (Sign Out):** `app.py` &rarr; `logout()`
  - `logout_user()` 및 `session.clear()`를 호출하여 서버 및 브라우저 세션을 즉시 파기.
- **4) 자료 조회 (Data Fetch):** `app.py` &rarr; `api_plans()`, `api_see_observation_stats()`
  - `@login_required` 데코레이터를 적용하고 `filter_by(user_id=current_user.id)`를 통해 본인 소유의 데이터만 엄격하게 필터링.

### ④ 안 열리는 것을 확인한 기록 (확인 5가지 대조)

```text
[확인 1: 비인가 접근 차단]
- 성공: [GET /api/plans] Cookie: session=ey...[생략] -> 200 OK (정상 인가)
- 거절: [GET /api/plans] 세션 쿠키 없음 -> 401 Unauthorized (로그인 화면 강제 리다이렉트)

[확인 2: 유효 계정 인증 vs 틀린 비밀번호]
- 성공: [POST /login] id: jychoi, pw: **** -> 200 OK (세션 쿠키 정상 발급)
- 거절: [POST /login] id: jychoi, pw: wrong_pass -> 401 Unauthorized ("비밀번호가 일치하지 않습니다")

[확인 3: 로그아웃 후 세션 재사용 방지]
- 성공: [POST /logout] -> 200 OK (세션 무효화)
- 거절: [GET /api/plans] 이전 세션 쿠키 session=ey...[생략] 재전송 -> 401 Unauthorized ("만료된 세션")

[확인 4: 타인 자료 접근 격리 (IDOR 방지)]
- 성공: [GET /api/plans] (user 1 세션) -> 200 OK (본인 계획 2건만 반환)
- 거절: [GET /api/plans/999] (타인 user 2 계획 조회 시도) -> 403 Forbidden ("권한 없음")

[확인 5: 타인 자료 수정/삭제 차단]
- 성공: [DELETE /api/plans/1] (본인 작성 계획) -> 200 OK
- 거절: [DELETE /api/plans/999] (타인 작성 계획) -> 403 Forbidden ("소유권 불일치")
```

### ⑤ AI와 나
- **AI에게 맡긴 일:** Flask `@login_required` 가드 라우터 데코레이터 및 5일 관찰 통계 수식(결측치 0 처리, Math.round 소수점 첫째 자리 집계) 보일러플레이트 코드 작성.
- **내가 직접 판단한 일:** 2일차 실천 후 3일차부터 90분 단위를 50분 뽀모도로 방식으로 축소 변경한 의사결정, 세션 만료 30분 타이머 정책 및 비밀번호 변경 시 이전 세션 일괄 무효화 UX 결정.
- **AI 말을 안 들은 일:** AI가 제안한 서드파티 외부 인증(Firebase/Supabase 클라우드 의존) 대신, SQLite 로컬 DB와 긴밀히 결합되어 외부 종속성이 없는 자체 완결형 세션 및 FIDO2 WebAuthn 표준 인증 아키텍처 채택.

### ⑥ 아직 못 막은 것 (보안 취약점 및 위험성)
- **미비점:** 단기간 반복 로그인 시도를 제한하는 무차별 대입 공격(Brute Force) 방지용 Rate Limiting(IP/계정당 시도 횟수 제한) 미구현.
- **위험성:** 악의적인 공격자가 자동화된 사전 대입 스크립트를 통해 무제한으로 비밀번호를 추측 시도할 경우, 단순한 비밀번호를 사용하는 사용자의 계정이 탈취될 수 있는 잠재적 위험이 존재함. (향후 개선: Flask-Limiter 도입 예정)

## 3. 화면 합계·평균과 손계산 검증표 (T07-C132)

### 수기 계산 검증 (손으로 더한 값)
1. **계획 시간 합계:** $90 + 90 + 100 + 100 + 100 = 480\text{분}$
2. **실행 시간 합계:** $75 + 62 + 90 + 95 + 90 = 412\text{분}$
3. **전체 누적 달성률 (Total Rate):**
   $$\frac{412}{480} \times 100 = 85.8333...\% \xrightarrow{\text{반올림}} \mathbf{85.8\%}$$
4. **일별 달성률의 산술 평균 (Average Rate):**
   $$\frac{83.333... + 68.888... + 90.0 + 95.0 + 90.0}{5} = \frac{427.222...}{5} = 85.444...\% \xrightarrow{\text{반올림}} \mathbf{85.4\%}$$

### 시스템 화면 표시값과 대조 결과
- **시스템 화면 합계:** 480분 중 412분 달성 (**85.8%**)
- **시스템 화면 평균:** 일평균 **85.4%**
- **오차:** **0.0% (완전 일치 / PASS)**
