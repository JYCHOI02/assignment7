## 1. 스크립트 모양 글자 점검 결과 (T06-C57)

### ① 점검 목적
- 사용자가 악의적인 자바스크립트 코드나 HTML 태그 형태의 문자열을 입력하더라도, 브라우저에서 스크립트가 실행(XSS 공격)되지 않고 **문자 모양 그대로 안전하게 표시**되는지 검증.

### ② 점검 대상 입력창
- 계획 제목 (`title`) 및 성공 기준 (`success_criteria`)
- 계획에 딸린 세부 할 일 제목 (`task_title`)
- 실행(DO) 시 실행 메모 (`memo`) 및 막혔던 이유 (`blocker_reason`)
- 돌아보기(SEE)에서 다음 계획으로 넘길 고칠 점 (`next_action_input`)

### ③ 테스트 입력 데이터
```html
<script>alert('XSS Attack!')</script>
<img src="x" onerror="alert('Img Error Attack')">
<svg onload="alert('SVG Attack')">
```

### ④ 기술적 구현 내용
1. **전역 HTML 엔티티 이스케이프 (`escapeHtml`) 구현**:
   - `static/script.js`의 `escapeHtml()` 유틸 함수를 통해 특수문자를 안전한 HTML 엔티티로 변환:
     - `&` → `&amp;`
     - `<` → `&lt;` (태그 시작 무력화)
     - `>` → `&gt;` (태그 종료 무력화)
     - `"` → `&quot;`
     - `'` → `&#039;`
2. **동적 HTML 렌더링 전수 적용**:
   - 계획 목록, 세부 할 일 목록, 실행 타임라인, 막힘 요인 모아보기, 최근 넘긴 고칠 점 칩 렌더링 시 모든 사용자 입력값을 `${escapeHtml(...)}`로 감싸서 브라우저가 스크립트로 해석하지 못하도록 원천 차단.
3. **안전한 DOM 속성 (`textContent`) 사용**:
   - 단순 텍스트 주입 영역은 `innerHTML` 대신 브라우저가 텍스트 노드로만 취급하는 `textContent` 속성을 적용.

### ⑤ 점검 결과
- **판정: PASS (정상 통과)**
- 스크립트 코드가 실행되어 팝업창(alert)이 뜨는 현상이 전혀 발생하지 않음.
- 계획 카드, 실행 이력 표, 돌아보기 화면에 입력한 스크립트 태그 문자열이 `<script>alert('XSS Attack!')</script>` 그대로 안전하게 화면에 렌더링됨.

## 2. 비밀값 점검 결과 (T06-C58)

### ① 점검 목적
- 브라우저 소스 코드, 배포 파일, 네트워크 API 응답, 브라우저 콘솔, Git 커밋 기록 어디에도 외부 API 키, 비밀번호, 서비스 토큰 등의 **비밀키 원문이 노출되지 않고 안전하게 관리**되는지 검증.

### ② 영역별 점검 내용 및 결과

| 점검 영역 | 점검 대상 파일/항목 | 점검 내용 및 기준 | 점검 결과 |
|---|---|---|---|
| **브라우저 코드** | `index.html`, `static/script.js`, `static/style.css` | API 키, 비밀키, 비밀번호 하드코딩 여부 | **노출 없음 (PASS)** |
| **배포/서버 파일** | `app.py`, 설정 파일 전반 | 소스 코드 내 비밀키/인증 토큰 원문 존재 여부 | **노출 없음 (PASS)** |
| **네트워크 응답** | 브라우저 Network 탭 (`/api/*` JSON 응답) | 서버 내부 디렉터리 경로, 환경 변수, DB 패스워드 등 민감 정보 포함 여부 | **노출 없음 (PASS)** |
| **브라우저 콘솔** | 개발자 도구 Console 탭 | 디버깅용 `console.log`에 인증 정보나 민감 데이터 출력 여부 | **노출 없음 (PASS)** |
| **Git 커밋 기록** | Git Repository 커밋 히스토리 전체 (`git log`) | 과거 커밋 및 diff 상에 비밀키가 커밋된 적이 있는지 여부 | **노출 없음 (PASS)** |

### ③ 기술적 무결성 근거
1. **Zero Hardcoded Secrets 구조**:
   - 본 시스템은 외부 유료 API나 원격 서드파티 서비스에 의존하지 않고 로컬 SQLite DB 기반으로 동작하도록 설계되어 소스 코드 내에 비밀키를 보관할 필요가 전혀 없음.
2. **API 응답 데이터 최소화 및 직렬화**:
   - Flask API 엔드포인트(`@app.route`)는 사용자에게 필요한 비즈니스 데이터(계획명, 시간, 완료 상태 등)만 정제하여 반환하며, 시스템 환경 변수나 내부 설정 정보를 일절 노출하지 않음.
3. **Git 기록 무결성**:
   - 프로젝트 최초 커밋부터 현재까지의 Git 히스토리를 전수 점검한 결과, 비밀키나 민감 설정 파일이 커밋된 이력이 전혀 없음.

### ④ 점검 결과
- **판정: PASS (정상 통과)**
- 브라우저 코드, 배포 파일, 네트워크 응답, 콘솔 로그, Git 기록 어디에도 비밀키 원문이 남아 있지 않음.

## 3. (참고) 데이터 영속성 및 돌아보기 연계 점검 결과 (T06-C34, T06-C35)

1. **실제 데이터베이스(DB) 저장 (T06-C34)**:
   - 서버의 로컬 SQLite 데이터베이스(`database.db`)에 계획(`plans`), 세부 할 일(`plan_tasks`), 실행 기록(`execution_records`), 개선 액션(`next_actions`) 테이블이 물리적 파일로 안전하게 커밋·저장됨.
2. **새로고침 후 동일 복원 (T06-C35)**:
   - 새로고침(F5) 후에도 브라우저가 서버 API를 호출하여 저장되어 있던 ID, 날짜, 수치, 단위 등을 100% 동일하게 복원함 (시크릿 창에서도 데이터 보존 확인 완료).
3. **돌아보기 고칠 점 다음 계획 연계**:
   - 돌아보기(SEE) 화면에서 등록한 고칠 점이 `next_actions` DB 테이블에 영구 저장되고, '다음 계획으로 넘기기' 클릭 시 PLAN 탭으로 자동 전환되며 새 계획 폼(제목, 성공 기준, 태그)에 자동 채움(Pre-fill)됨.
