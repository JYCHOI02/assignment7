T07 카드 5: 인증 구현 설명서 (증빙 01)

01_인증구현설명서.png

본 문서는 과제 T07 심사를 위한 6개 항목 필수 인증 구현 명세서입니다. (모든 비밀값·토큰은 마스킹 처리됨)

① 무엇으로 붙였나

  • 비밀번호 해시 & 인증: Werkzeug Security (PBKDF2 SHA-256 + Salt) 솔팅 해시 암호화
  • 세션 관리: Flask-Login 기반 서버 사이드 세션 및 30분 유효기간 타이머, HttpOnly SameSite 쿠키
  • 생체인증(패스키): FIDO2 / WebAuthn 표준 생체인식 (지문, Face ID, Windows Hello)
  • 원격 모바일 간편인증: Cloudflare Tunnel / Ngrok 연동 원격 모바일 QR 세션 로그인 체계

② 왜 그걸 골랐나

  • 사용자 격리 및 Zero Vendor Lock-in: 외부 유료 SaaS(Firebase, Supabase 등)에 종속되지 않고 로컬 SQLite DB와 연계하여 사용자별 데이터(user_id)를 완전 분리 격리.
  • 웹 표준 보안 충족: FIDO2 패스키 표준을 준수하여 비밀번호 없이도 기기 생체인식으로 간편하고 안전하게 로그인 가능.
  • 정적/모바일 환경 확장성: PC 브라우저뿐만 아니라 스마트폰 카메라로 QR을 스캔하여 모바일과 데스크톱 간 끊김 없는 인증 세션 인계 지원.

③ 어디를 어떻게 고쳤나 (핵심 흐름 4가지)

1) 회원가입 (Sign Up): app.py → register()
- generate_password_hash(password, method='pbkdf2:sha256') 솔팅 해시 생성 후 User DB 저장
2) 로그인 (Sign In): app.py → login()
- check_password_hash() 검증 후 login_user() 세션 생성, 30분 만료 타이머 설정 및 마지막 접속 시각 갱신
3) 로그아웃 (Sign Out): app.py → logout()
- logout_user() 및 session.clear()로 활성 세션 쿠키 즉시 무효화
4) 자료 조회 (Data Fetch): app.py → api_plans(), api_see_observation_stats()
- @login_required 가드 검증 및 filter_by(user_id=current_user.id)로 본인 소유 데이터만 엄격히 조회·격리

④ 안 열리는 것을 확인한 기록 (확인 5가지 대조)

[확인 1: 비인가 접근 차단]
- 성공: [GET /api/plans] Cookie: session=ey...[생략] → 200 OK
- 거절: [GET /api/plans] 세션 쿠키 없음 → 401 Unauthorized (로그인 화면 강제 리다이렉트)
[확인 2: 유효 계정 인증 vs 틀린 비밀번호]
- 성공: [POST /login] id: jychoi, pw: **** → 200 OK (세션 정상 발급)
- 거절: [POST /login] id: jychoi, pw: wrong_pass → 401 Unauthorized ("비밀번호가 일치하지 않습니다")
[확인 3: 로그아웃 후 세션 재사용 방지]
- 성공: [POST /logout] → 200 OK (세션 무효화)
- 거절: [GET /api/plans] 이전 세션 ey...[생략] 재전송 → 401 Unauthorized ("만료된 세션")
[확인 4: 타인 자료 접근 격리 (IDOR 방지)]
- 성공: [GET /api/plans] (user 1 세션) → 200 OK (내 계획 2건만 반환)
- 거절: [GET /api/plans/999] (타인 user 2 계획 조회 시도) → 403 Forbidden ("권한 없음")
[확인 5: 타인 자료 수정/삭제 차단]
- 성공: [DELETE /api/plans/1] (본인 작성 계획) → 200 OK
- 거절: [DELETE /api/plans/999] (타인 작성 계획) → 403 Forbidden ("소유권 불일치")

⑤ AI와 나

  • AI에게 맡긴 일: Flask @login_required 가드 라우터 데코레이터 구성 및 5일 관찰 통계 수식(결측치 0 처리, Math.round 소수점 첫째 자리 집계) 보일러플레이트 코드 작성
  • 내가 직접 판단한 일: 2일차 실천 후 3일차부터 90분 단위를 50분 뽀모도로 방식으로 축소 변경한 의사결정, 세션 만료 30분 타이머 정책 및 비밀번호 변경 시 이전 세션 일괄 무효화 UX 결정
  • AI 말을 안 들은 일: 외부 서드파티 OAuth/SaaS(Firebase) 의존 제안을 배제하고, SQLite 로컬 DB와 긴밀히 결합된 자체 완결형 세션 및 FIDO2 WebAuthn 표준 인증 아키텍처 채택

⑥ 아직 못 막은 것 (보안 취약점 및 위험성)

  • 미비점: 단기간 반복 로그인 시도를 제한하는 무차별 대입 공격(Brute Force) 방지용 Rate Limiting(IP/계정당 시도 횟수 제한) 미구현.
  • 위험성: 악의적인 공격자가 자동화된 사전 대입 스크립트를 통해 무제한으로 비밀번호를 추측 시도할 경우, 단순한 비밀번호를 사용하는 사용자의 계정이 탈취될 수 있는 잠재적 위험이 존재함. (향후 개선: Flask-Limiter 도입 예정)
