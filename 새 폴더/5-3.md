T07 최종 제출물인 '인증 구현 설명서'를 작성해 주세요. 
반드시 아래 6가지 번호 항목으로 나누어 작성하고, 마스킹 규칙을 엄격히 적용해 주세요:
(주의: 비밀번호, JWT 토큰, API Key 등 비밀값 원문 절대 금지. 예: 'eyJhbGciOi...[생략]', 'pass****' 로 마스킹 필수)

[① 무엇으로 붙였나]
- 사용한 인증 라이브러리/기술 스택 명시 (예: Firebase Auth, Supabase Auth, 또는 JWT + Web Crypto / LocalStorage 등)

[② 왜 그걸 골랐나]
- T06 정적 웹 구조(GitHub Pages)와의 호환성, 클라이언트 사이드 보안 유지, 구현 복잡도 등을 고려한 선택 이유

[③ 어디를 어떻게 고쳤나 (T07-C128)]
- 다음 네 가지 핵심 흐름이 소스 코드의 어떤 파일, 어떤 함수를 통과하는지 구체적 경로/함수명 작성:
  1) 회원가입 (Sign Up)
  2) 로그인 (Sign In)
  3) 로그아웃 (Sign Out)
  4) 자료 조회 (내 다이어리 목록 Fetch 및 본인 인증 체크)

[④ 안 열리는 것을 확인한 기록 (T07-C129)]
- 다음 5가지 시나리오에 대해 각각 '성공 요청/응답'과 '거절/실패 요청/응답(HTTP 상태코드 포함)'을 나란히 대조하여 작성:
  1) 비로그인 상태에서 보호된 다이어리 데이터 직접 URL/API 접근 시도 -> 거절(401/리다이렉트)
  2) 올바른 인증 정보로 접근 -> 성공(200 OK)
  3) 로그아웃 후 이전 토큰/세션 재사용 시도 -> 거절(401 Unauthorized)
  4) 다른 사용자 계정의 데이터 ID 읽기/수정/삭제 시도 -> 거절(403 Forbidden)
  5) 유효하지 않은 비밀번호로 로그인 시도 -> 거절(400/401)
  *(단, 본문의 모든 토큰/암호는 마스킹 처리)*

[⑤ AI와 나 (T07-C40)]
- AI에게 맡긴 일: 인증 로직 보일러플레이트 코드 작성 및 정규식 검증
- 내가 직접 판단한 일: 세션 만료 시간 정책 및 비인가 접근 시 화면 전환 UX 결정
- AI 제안을 따르지 않은 일: (구체적 사례 및 이유 서술)

[⑥ 아직 못 막은 것 (T07-C130)]
- 비워두지 말고, 현재 구현에서 아직 보완하지 못한 보안 취약점 1~2개 서술 (예: 무차별 대입 공격(Brute Force) 방지를 위한 Rate Limit 미구현, 토큰 탈취 방지를 위한 HttpOnly 쿠키 미사용 등)
- 그것이 왜 시스템이나 사용자에게 위험한지 기술적 영향 서술
